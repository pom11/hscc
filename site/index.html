hscc

hscc looks after a small cluster of AI computers for you.

What it is

You have a few machines that run AI models, and a team of AI helpers that do your work on them. hscc is the manager in between: it starts the models, keeps them running, hands work to the right helper, and restarts anything that falls over — then tells you only when it actually needs you.

You watch all of it from your phone or your Mac, without opening a terminal.

Get it Source on GitHub

Why

One tool instead of ssh + docker + a folder of your own scripts.

One command brings the fleet up or down.

No logging into each machine, no remembering which container runs what.

The models stay up on their own.

A watchdog keeps checking the serving path and restarts a model that died; if it can't fix it, it stops retrying and tells you why.

Templates switch what the cluster serves.

One command turns the same hardware from "one big brain" into "one brain plus a team of coders".

Agents work on task boards you can actually read.

Orchestrator agents take a goal, split it into cards, and workers pick the cards up — with a review step before anything lands.

You see everything from your phone or Mac.

Six widgets, Live Activities, and a menu-bar tile — no laptop required.

What it does

🖥️ Runs the fleet

Starts and stops the models on every machine, from one place.

🩺 Watches it constantly

Health checks for the machines, the serving gateway, storage, and the AI agents themselves.

🔁 Heals what it can

Restarts a dead model on its own, and speaks up when it can't.

💤 Saves power when idle

Puts the GPU serving layer to sleep after a quiet period and wakes it when work arrives.

📋 Runs agents on boards

Cards for todo / ready / running / blocked / done, per project, with a standup digest.

📱 Shows it on your devices

The same state as widgets on iOS and macOS, plus live tiles on the Lock Screen and Dynamic Island.

Templates

A template is a picture of your cluster written down.

It says: this many machines, this model here, these workers there. Applying a template rebuilds the cluster to match the picture — so switching what your hardware does is one command, not an afternoon.

hscc template preview <name> shows what would change before anything moves; hscc template apply <name> --confirm makes it real.

Commands

The whole tool is one command, hscc. This is every command group, in the order the tool lists them.

Daemon control

The background watcher that does the checking and the healing.

  • hscc startstart the watcher in the background.
  • hscc stopstop it gracefully.
  • hscc statusis everything healthy? One screen: the watcher plus the last result of every health check.
  • hscc installmake the watcher start by itself when the machine boots.
  • hscc uninstallremove that auto-start and stop the watcher.
  • hscc plistprint the auto-start config without installing it.
  • hscc logread what the watcher has been saying.

Health & monitoring

  • hscc checkrun the health checks now instead of waiting, or just one stream (machines, gateway, local, heartbeat, storage, watchdog, triggers).
  • hscc check --repo <path>is a given checkout still protected by the commit-time leak guard? Says so plainly when it isn't.
  • hscc watchfollow the check results live.
  • hscc triggersthe alert rules and what fired recently.
  • hscc verifyone long smoke test of the whole cluster.
  • hscc statswhat the fleet has been doing over the last N days.
  • hscc throughputhow fast the models are answering and how deep the queue is, across the fleet.
  • hscc autoscalewhat the autoscaler would decide right now, without doing it.
  • hscc escalatewhich failures are waiting for a human, without touching them.

Cluster & templates

  • hscc cluster statuswhat is running and which machines are idle.
  • hscc cluster hostsevery machine and every saved cluster you know about.
  • hscc cluster monitorCPU, memory and GPU per machine; --live adds the load per model.
  • hscc cluster jobsevery job running right now.
  • hscc cluster infothe resolved cluster configuration in detail.
  • hscc cluster stop <id>stop one running workload.
  • hscc cluster downstop every workload on the fleet (--dry-run first).
  • hscc cluster upstart every unit the serving config declares (--dry-run first).
  • hscc template listevery template we ship.
  • hscc template statuswhich template is applied right now.
  • hscc template preview <name>a dry run: what applying it would change.
  • hscc template validate <name>check a template offline and against the live cluster.
  • hscc template apply <name> --confirmrebuild the cluster to match the template.
  • hscc profileshow many cards each agent role is holding.
  • hscc project …mission control for several projects at once: standup, decompose, review, qa, verify, doctor, metrics and more.
  • hscc api startthe read-only HTTP API your phone and Mac read from; prints the pairing QR code (stop / status too).
  • hscc autodownthe idle sleep/wake for the GPU layer: status, enable, disable, wake, cancel.
  • hscc kanbanboard hygiene: blocked cards (list and recover), stale cards (list and archive), and a live board monitor.
  • hscc cards monitorone live panel per running card, streaming what its worker is doing.
  • hscc orch injectsend a message into a running agent's session.
  • hscc orch wakerthe built-in orchestrator waker: status, enable, disable.

Utility

  • hscc notify "<title>" "<body>"post an alert to the feed the iOS and macOS apps read (--level, --key). hscc notify test sends one test push to the registered devices.
  • hscc bootstrapthe installer, runnable from a repo checkout, a plugin tree or a Homebrew install.
  • hscc update --checkask GitHub whether a newer release exists. Reads only; it never installs anything.

How it looks

Six widgets, the same six on iPhone and on the Mac desktop, so the cluster is a glance instead of a login:

Cluster

Is it serving, waking up, or down, with a small map of the machines and how long before an idle cluster goes to sleep.

Monitor

CPU, memory and GPU per machine.

Running cards

The jobs being worked right now, who is doing them, and for how long.

Kanban monitor

Running, ready and blocked at a glance.

Board status

Todo / ready / running / blocked / done for one board you pick.

Projects

Your projects and the board each one owns.

Live Activities

Put the same information on the Lock Screen and the Dynamic Island while something is happening: the cluster waking, models serving, cards running, a board making progress, or the fleet's overall health.

You can restyle it.

One global style for every widget and Live Activity, or a different one per tile — colour (including a transparent background), font, weight, text size, density, and whether the header and icons show. Presets get you most of the way there, and everything has a live preview.

Get it

CLI (Mac or Linux control host):

brew tap pom11/hscc
brew install hscc
hscc bootstrap --yes

iPhone app:

Open https://pom11.github.io/hscc/ios/ in Safari on the iPhone and tap Install.

It's an Ad Hoc build, so your device has to be registered with the maintainer first — see ios-app/INSTALL.md.

Mac menu-bar app + desktop widgets:

brew install --cask pom11/hscc/hscc-widgets

The code:

https://github.com/pom11/hscc (MIT).

You'll need a configured sparkrun DGX Spark cluster and Hermes on the control host — hscc is the manager layer, not the hardware.
