hscc

hscc looks after a small cluster of AI computers for you.

What it is

You have a few machines that run AI models, and a team of AI helpers that do your work on them. hscc is the manager in between: it starts the models, keeps them running, hands work to the right helper, and restarts anything that falls over — then tells you only when it actually needs you.

You watch all of it from your phone or your Mac, without opening a terminal.

Get it Source on GitHub

Why

One tool instead of ssh + docker + a folder of your own scripts.

One command brings the fleet up or down.

No logging into each machine, no remembering which container runs what.

The models stay up on their own.

A watchdog keeps checking the serving path and restarts a model that died; if it can't fix it, it stops retrying and tells you why.

Templates switch what the cluster serves.

One command turns the same hardware from "one big brain" into "one brain plus a team of coders".

Agents work on task boards you can actually read.

Orchestrator agents take a goal, split it into cards, and workers pick the cards up — with a review step before anything lands.

One agent runs the whole show.

Bootstrap creates one main orchestrator, named general unless you pick another name. It knows every project and the cluster, watches the boards, steers the other orchestrators, and does everything except a LIVE publish.

Green PRs merge in order, not all at once.

The local merge queue rebases each one onto the latest main, runs the project's gates, and merges it. It is on by default for GitHub projects that declare gates.

You see everything from your phone or Mac.

Five widgets, Lock Screen gauges, one Live Activity, and a menu-bar app — no laptop required.

What it does

🖥️ Runs the fleet

Starts and stops the models on every machine, from one place.

🩺 Watches it constantly

Health checks for the machines, the serving gateway, storage, and the AI agents themselves.

🔁 Heals what it can

Restarts a dead model on its own, and speaks up when it can't.

💤 Saves power when idle

Puts the GPU serving layer to sleep after a quiet period once you turn autodown on, and wakes it when work arrives.

⏸️ Parks one machine when you need it

hscc node pause <host> frees a machine for a training run without editing a template or the serving config: you confirm the plan it prints before anything stops, the pause is a durable record the heal, wake and fleet-up paths honour, and the widgets, the CLI and the API all show it as paused (reason, since). --until 2h gives the machine back by itself.

📋 Runs agents on boards

Cards for todo / ready / running / blocked / done, per project, with a standup digest.

🧭 Keeps one agent in charge

The main orchestrator, general by default, wakes on a schedule, checks every board and pane, and does everything except a LIVE publish, which asks you first.

🔀 Merges green PRs in order

One local queue rebases, gates and squash-merges one PR at a time; hscc merge-queue status shows the queue.

📱 Shows it on your devices

Five widgets on iOS and macOS, Lock Screen gauges, one Live Activity, and a CarPlay screen. There are no push notifications to configure.

Templates

A template is a picture of your cluster written down.

It says: this many machines, this model here, these workers there. Applying a template rebuilds the cluster to match the picture — so switching what your hardware does is one command, not an afternoon.

hscc template preview <name> shows what would change before anything moves; hscc template apply <name> --confirm makes it real.

Commands

The whole tool is one command, hscc. This is every command group, in the order the tool lists them.

Daemon control

The background watcher that does the checking and the healing.

  • hscc startstart the watcher in the background.
  • hscc stopstop it gracefully.
  • hscc statusis everything healthy? One screen: the watcher plus the last result of every health check.
  • hscc installmake the watcher start by itself when the machine boots.
  • hscc uninstallremove that auto-start and stop the watcher.
  • hscc plistprint the auto-start config without installing it.
  • hscc logread what the watcher has been saying.
  • hscc start-daemonrun the watcher loop in the foreground yourself (normally launchd runs it).

Health & monitoring

  • hscc checkrun the health checks now instead of waiting, or just one stream (dgx, gateway, local, heartbeat, nas, watchdog, triggers).
  • hscc check --repo <path>is a given checkout still protected by the commit-time leak guard? Says so plainly when it isn't.
  • hscc watchfollow the check results live.
  • hscc triggersthe alert rules and what fired recently.
  • hscc verifyone long smoke test of the whole cluster.
  • hscc statswhat the fleet has been doing over the last N days.
  • hscc throughputhow fast the models are answering and how deep the queue is, across the fleet.
  • hscc autoscalewhat the autoscaler would decide right now, without doing it.
  • hscc escalatewhich failures are waiting for a human, without touching them.
  • hscc heal-clear <node>clear one machine's heal-breaker strikes; this mutates the ledger, and --help clears nothing. Not the /heal chat command.
  • hscc heal-statuslist the heal-breaker strikes per machine, read-only. Not the /heal chat command, which restarts unhealthy workers instead.

Cluster & templates

  • hscc cluster statuswhat is running and which machines are idle.
  • hscc cluster hostsevery machine and every saved cluster you know about.
  • hscc cluster monitorCPU, memory and GPU per machine; --live adds the load per model.
  • hscc cluster jobsevery job running right now.
  • hscc cluster infothe resolved cluster configuration in detail.
  • hscc cluster stop <id>stop one running workload.
  • hscc cluster downstop every workload on the fleet (--dry-run first).
  • hscc cluster upstart every unit the serving config declares (--dry-run first).
  • hscc template listevery template we ship.
  • hscc template statuswhich template is applied right now.
  • hscc template preview <name>a dry run: what applying it would change.
  • hscc template validate <name>check a template offline and against the live cluster.
  • hscc template apply <name> --confirmrebuild the cluster to match the template.
  • hscc profileshow many cards each agent role is holding.
  • hscc project …mission control for several projects at once: standup, decompose, review, qa, verify, doctor, metrics and more.
  • hscc api startthe read-only HTTP API your phone, Mac and CarPlay screen read from; prints the pairing QR code (stop / status too).
  • hscc autodownthe idle sleep/wake for the GPU layer, off until you enable it: status, enable, disable, wake, cancel.
  • hscc kanbanboard hygiene: blocked cards (list and recover), stale cards (list and archive), and a live board monitor.
  • hscc merge-queuethe local queue of green PRs, on by default for GitHub projects with gates: status, list, add, remove, pause, resume, enable, disable.
  • hscc cards monitorone live panel per running card, streaming what its worker is doing.
  • hscc mainthe main orchestrator (general by default): bring its pane up, see whether it is busy, and edit the wake-up schedule the watcher fires into it.
  • hscc orch injecttype a message into a running agent's live pane. (Three other things share the "orch" name and are not this: the orch_message agent tool, the /orch-restart chat command, /v1/orchestrator/chat.)
  • hscc orch wakerthe built-in orchestrator waker: status, enable, disable.
  • hscc node pause <host>park one machine and only that machine. It prints the plan — the host, every model it would stop, the reason, the deadline — then asks Pause <host> and stop these N model(s)? [y/N]: only y proceeds, Enter or n records nothing, --yes answers it for a script (without it a run with no terminal refuses), and --dry-run previews without asking. It refuses, recording nothing, when a model on the machine also runs on other machines — naming that model and its peers — or when the machine runs no models at all. --force is only for the guard on the machine your orchestrator model runs on. hscc node resume <host> confirms the same way and starts the recorded models back up; hscc node paused lists what is parked, read-only.

Utility

  • hscc notify "<title>" "<body>"post an alert to the feed (--level, --key); hscc notify list reads it newest first (--since, --limit, --json) and hscc notify ack marks one seen. The feed is what the Needs Me widget shows; hscc sends no push notifications.
  • hscc bootstrapthe installer, runnable from a repo checkout, a plugin tree or a Homebrew install; it creates the main orchestrator and its board.
  • hscc update --checkask GitHub whether a newer release exists. Reads only; it never installs anything.

How it looks

Five widgets — Cluster, Boards, Running, Needs Me and Merge Queue — the same five on iPhone and on the Mac desktop, in a Native look: system colours, SF Pro Rounded numbers, and colour used only for state.

Cluster

Is it serving, waking up, or down, with throughput and a row per machine showing load and temperature.

Boards

Open cards per board as stacked bars (running, todo, blocked), with the worker-slot cap and cards done today.

Running

The longest-running card, its elapsed time and a heartbeat, then the other cards being worked right now.

Needs Me

What is waiting for you from the alert feed, and a calm "All clear" when nothing is. It says "All clear" only when the last check actually succeeded; a failed check shows offline instead.

Merge Queue

The PR at the front of the local merge queue, its stage (rebase, gates, push, merge), what is waiting behind it, and the last result.

Lock Screen

All five also have gauge layouts for the Lock Screen, so a glance shows the hottest node, worker slots, the longest run, what needs you, or the merge queue.

One Live Activity: Cluster watch.

It puts the cluster's serving state on the Lock Screen and in the Dynamic Island: four node columns with temperature and load, throughput, the daemon state and whether autodown is off. It starts from the app's Cluster screen and ends after 8 hours or when you stop it.

A CarPlay screen

Shows cluster health, boards, running work, what needs you and the merge queue on the car display. It runs in Apple's CarPlay simulator today; shipping it on the road needs Apple's CarPlay entitlement, which hscc does not have yet.

Fresher widgets on the Mac.

iPhone widgets refresh about every 30 minutes, the most often iOS allows, and whenever you open the app. On the Mac, the menu-bar app can refresh the desktop widgets every 1, 2, 5 or 15 minutes while it runs (Settings → Desktop Widgets). Every widget shows how old its data is.

No push notifications.

hscc does not ask for notification permission and sends nothing to your phone. The Needs Me widget is the at-a-glance view, and hscc notify list is the full alert feed on the command line.

Get it

CLI (Mac or Linux control host):

brew tap pom11/hscc
brew install hscc
hscc bootstrap --yes

iPhone app:

Open https://pom11.github.io/hscc/ios/ in Safari on the iPhone and tap Install.

It's an Ad Hoc build, so your device has to be registered with the maintainer first — see ios-app/INSTALL.md.

Mac menu-bar app + desktop widgets:

brew install --cask pom11/hscc/hscc-widgets

The code:

https://github.com/pom11/hscc (MIT).

You'll need a configured sparkrun DGX Spark cluster and Hermes on the control host — hscc is the manager layer, not the hardware.
