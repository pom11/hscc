- all four targets **compile and link** (HSCC 56 files, HSCCWidgets 6,
  HSCCLiveActivity 4, HSCCLiveActivitySession 4 — 0 errors)
- all 61 Swift sources are **registered** in `project.yml`
- 31/31 response fixtures **decode against the real Codable models**
- eight logic harnesses pass (`first_run`, `chat_state`, `streaming`,
  `session_activity`, `reconnect`, `model_decode`, `check_sources`, `check_theme`)

**Not proven, and not provable here:**

**The device smoke checklist remains the gate.** This report reduces the odds of

## Findings by severity

### HIGH — would have cost you the first hour

**H1 · Missing Info.plist keys** — `ios-app/project.yml`
`NSSupportsLiveActivities` and `NSCameraUsageDescription` were not declared in
the target's `info: properties:` block. Without the camera key **iOS terminates
the app the instant the QR scanner opens**, which is your first action.

The mechanic matters more than the fix: `Sources/Info.plist` and every extension
plist are **generated by XcodeGen from `project.yml`**. A key hand-added to the
generated file survives only until the next `generate.sh`. Yesterday's fix had
exactly that flaw and would have silently vanished. Both keys are now declared at
the source, verified by regenerating and re-reading all four plists (`plutil
-lint` clean). Fixed in `188870d`.

**H2 · The app could look configured while nothing worked** — `SetupQRCode.swift`, `Views/SettingsView.swift`
Two independent paths stored an unusable token and reported success:
`SetupQRCode.decode` accepted a **whitespace-only** token (it checked `isEmpty`
without trimming, while trimming the host), and `SettingsView.save()` stored the
token **untrimmed** — so a token pasted from terminal output with a trailing
newline persisted with the whitespace. Worse, the Test-connection gate *did*
trim for its check, so the test passed while the stored value differed.

Either way the app showed "configured", every request 401'd, and nothing in the
UI explained why. Fixed in `5e97d86`; `first_run_check.sh` (14 assertions) locks
the decode contract. Verified `applyScanned()` routes through `save()`, so the
trim covers the QR path too.

**H3 · A rotated token hung the stream forever** — `Views/StreamingChatStore.swift`
When a token is rejected the server answers the WebSocket upgrade with a non-101
response. `socketClosed` **ignored the error** and reconnected indefinitely: you
would have watched "Reconnecting…" forever with no hint the token was at fault,
while the REST path was already telling you to check it. Now classified in
`StreamConnectionError.swift` (`-1011` → `.rejected`, everything else
`.transient`) and surfaced honestly. Fixed in `39787f3`; `reconnect_check.sh`
proves 31 assertions including four transport codes that must stay transient.

### MED

**M1 · Reply poll leaked across view teardown** — `Views/OrchestratorChatView.swift:400,425`
`pollTask` was an *unstructured* Task created outside the `.task` modifier, and
`.onDisappear` never cancelled it. Navigating away with a reply in flight left a
2-second poll loop writing `@Published` mutations into a torn-down `ChatStore`,
holding the view and its `@StateObject` alive — battery drain plus state
corruption on a phone. Fixed in `3a95ec8`, matching `TemplateDetailView:86`.

**M2 · Reconnect backoff never reset** — `Views/StreamingChatStore.swift`
The attempt counter only ever grew, so after the first drop **every** later
reconnect waited the 15s ceiling for the rest of the session. Reset where the
hello frame confirms the stream is live. Fixed in `1a3030e`.

**M3 · Four API routes returned errors inside a 200** — `routes_template.py:117,128`, `routes_cluster.py:370,380`
These read handlers forwarded a raw backend `{"error": ...}` dict into a 200
body instead of the contract shape — **the app would have decoded that as
success**. Now degrade to a clean `200 {"speak": "… unavailable."}`, matching the
existing status/hosts/info/profiles pattern, with tests locking the shape. Fixed
in `d0cdff8`.

**M4 · Keychain save failure was silent** — `Views/SettingsView.swift`
The token write status was ignored on plain Save, so a saved host/port looked
like a saved **connection** while the app read back "not configured". A failed
older-page fetch in Session History was likewise swallowed. Both now surfaced
(the Keychain one reports the OSStatus). Fixed in `d0cdff8`.

**M5 · Tests could have written your live profiles** — `hscc_daemon/serving.py:524,551-557`
The autouse isolation fixture did not redirect `serving.PROFILES_DIR` (nor
`ORCH_ENDPOINT_STATE`, `SERVING_JSON`, `CLUSTER_JSON`, `hscc.PROFILES_DIR`), and
`serving.update_orchestrator_followers()` **iterates `PROFILES_DIR` and rewrites
`config.yaml` under `~/.hermes/profiles`**. The suite was safe only because every
test that reached it happened to patch manually — one new test forgetting would
have written live operator profiles. This is the **fifth** instance of this
project's recurring live-state class. Closed with a hardened fixture and a guard
test in `8b37d11`.

**M6 · The theme guard failed on the sites it was meant to permit** — `ios-app/scripts/check_theme.sh`
Its allowlist pinned **exact line numbers**; unrelated cherry-picks shifted those
lines and the guard began flagging the very sites it exempts. Re-anchored on
inline `// theme-allow: <why>` markers that travel with the code, and
negative-tested in both directions. Fixed in `76dd76a`.

## Audited clean — with proof, not assumption

**API authentication.** All **79 routes** (78 HTTP + 1 WebSocket) are gated by a
single central `_authorize()`. I verified in the code that it is the **first
statement** of `_route()` (`hscc-api/api_server.py:505`) — ahead of path parsing
and ahead of the WebSocket upgrade branch — so the 101 handshake cannot precede
auth. The bind refuses `0.0.0.0` (`_REFUSED_BINDS`, `api_server.py:197`). A new
table-driven `test_auth_all_routes.py` (158 assertions) covers newly added routes
automatically and was **mutation-tested**: breaking the gate makes it fail.

**Secrets.** The live 43-character API token appears **0 times in tracked files
and 0 times across all git history** (`git log --all -S`). Token file mode `600`,
`~/.hscc` directory `700`, and the iOS side stores it in the Keychain, never
`UserDefaults`. The worker **retracted its own earlier false positive** about a
token in `events.jsonl` history — correctly, which is what prevented a needless
history rewrite.

**Test hermeticity.** I reproduced the proof independently: snapshotted 63
operator-state files, ran the full suite (ALL GREEN), re-snapshotted and
content-diffed. **Exactly two files changed, both pure daemon writes** —
`autodown.json` advanced only `last_activity_iso`, `watchdog-block.json` rotated
only its `failures[]` timestamps. Zero of 39 profile `config.yaml` changed.

**Clean-clone build.** A fresh clone tests green, generates the iOS project and
compiles all four targets using only documented environment variables.
`generate.sh` correctly **refuses** when `HSCC_DEVELOPMENT_TEAM` is unset
(`generate.sh:45-63`) rather than writing the literal placeholder into the
project.

## Mistakes I made during this audit

Stated plainly, because they affect how much you should trust the rest.

1. **I leaked your tailnet IP to the public repo.** An audit report quoted the
   live address. I scrubbed it in the working tree but **never committed the
   scrub before pushing**, and my leak check grepped working-tree files — so it
   passed while the committed blob still carried it. `origin/main` HEAD is clean
   (`3c66339`), but the address remains in **one pushed commit, `a7c3303`**. I did
   **not** force-push a history rewrite; that is your call. It is a private CGNAT
   address, meaningful only to someone already on your tailnet. Leak checks now
   read committed blobs via `git show`.

2. **Three times a worker's "CLEAN" was true on its base and false on current
   dev** — the theme guard, and a stale docs claim left beside a fixed one. Any
   check must be re-run after cherry-picking, not inherited from the report.

3. **Twice I ran the suite in the foreground** and hit the 10-minute tool cap,
   killing it mid-run and wasting a cycle.
