# t_8306890e — Dispatcher worktree placement fix (configurable root + relocate EcoFire worktrees)

## Problem
The kanban dispatcher creates worktrees at `<repo>/.worktrees/<id>` (hardcoded in
hermes-agent `hermes_cli/kanban_db_workspace.py::_anchored_worktree`). For
/Users/desac/dev/EcoFire_customizations_bc the project root IS the AL compiler root,
so the compiler walks the `.worktrees/` dirs and compiles half-finished branch code:
baseline 2487 files, 1,991 of them worktree noise, AL1021 error. `.gitignore` does
NOT fix this (git ignoring a path does not stop a compiler walking the filesystem),
and AL has no app.json exclude key. The fix is PLACEMENT.

Decision: register EcoFire_customizations_bc + ecofire + efsdriver in
kanban.worktree.out_of_tree_repos so ALL FUTURE dispatches place their worktrees out
of tree. Relocate ONLY the 4 mandated EcoFire worktrees now (the other repos' existing
.worktrees/ belong to boards that may have running cards; leave in place, flag as
follow-up so we don't yank a live worker's CWD).

## Config shape (decided)
Under ~/.hermes/config.yaml:
  kanban:
    worktree:
      # Repos whose project root is itself a build/compiler root — in-tree
      # .worktrees/ under them get compiled as part of the app. Their worktrees
      # are placed OUT of tree under out_of_tree_root/<repo-name>/<task-id>.
      out_of_tree_repos:
        - /Users/desac/dev/EcoFire_customizations_bc
      out_of_tree_root: ~/dev/.worktrees
Matching is done by repo_root prefix comparison (same as existing .worktrees
detection). Default (no config) = in-tree .worktrees/, fully backwards compatible.
