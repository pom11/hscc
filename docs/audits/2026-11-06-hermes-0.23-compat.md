5. **Patch `0011` (`started_at` on reclaim and fresh claim) → REBASE:**
   - What upstream `v0.23.0` changed:
     - Upstream added `worker_started_at` (process spawn fingerprint) alongside `started_at` (`hermes_cli/kanban_db.py:812,920-926`), plus `hermes_cli/kanban_owner_recovery.py:1-250` (`owner_attempt_provably_over`, `apply_attempt_note`) so dead managed attempts free their slot while a dropped socket resumes the same attempt.

   - Why this still breaks HSCC checks and upstream's own crash grace:
     - **HSCC stale / age checks:** `hscc-project/flightdeck/core/kanban.py:548,1239-1243` (`_to_card` and `reconcile_plan` stale check `_older_than(card, stale_threshold_seconds, field="started_at")`), `hscc_daemon/kill_switch.py:100-103,166-185`, `hscc_daemon/hscc.py:84-95` (`_kanban_task_status`), and `scripts/worker_progress.sh:9-10` all read `tasks.started_at` directly, not `task_runs.started_at`. When a reclaimed task is re-claimed with `tasks.started_at` still holding an old timestamp from hours ago, a freshly re-spawned worker gets **zero** launch-window crash grace on retry!

## 3. Behaviour Changes That Affect HSCC Operating Procedures

### 3.1 `Ctrl+C` Draft-Clear vs Turn Interrupt (`repl_inject`, `orch-rolling`, and Steer/Interrupt)
- **What changed upstream:**
  - In both the classic CLI (`hermes_cli/cli_tui_mixin.py:926-952`, `_tui_handle_ctrl_c`) and the Ink TUI (`ui-tui/src/app/useInputHandlers.ts:90-108`), `Ctrl+C` checks whether the composer buffer has a draft **first**:
    - If a draft or image is in the composer (`event.app.current_buffer.text or self._attached_images`), `Ctrl+C` **only clears the draft** and does **not** interrupt the running turn (`cli_tui_mixin.py:928,941,950-951`: *"clear a typed draft, even mid-run (a correction must never kill the turn)"*).
    - If the composer buffer is **empty** while a turn is running, `Ctrl+C` **still interrupts the running turn** (`cli_tui_mixin.py:941-949`, `request_hard_interrupt(self.agent)`).
  - Additionally, `Ctrl+D` mid-turn in the classic CLI now detaches instead of interrupting (`v0.23.0.md:210`).
- **What are the interrupt keys/commands in `v0.23.0`?**
  1. **Submitting a plain message while busy (`msg=interrupt`)**: Still interrupts the running turn and starts a new turn with that message (`locales/en.yaml:2263`: `placeholder_busy: "msg=interrupt · /queue · /bg · /steer · Ctrl+C cancel"`). Because `hscc-api/repl_inject.py:57,60-74,387-440` (`mode="plain"` / legacy `mode="interrupt"`) pastes text and presses Enter (`\r`), and `mode="steer"` pastes `/steer <text>` and presses Enter, **`repl_inject` does not use `Ctrl+C` and continues to work!**
  2. **Slash command `/stop`**: Interrupts the running turn (and in `v0.22.0+` also stops background subagents and hands back their partial work; `v0.22.0.md:35`, `hermes_cli/gateway_chat_view.py:370`).
  3. **`Ctrl+C` or `Ctrl+Q` on an empty buffer**: Interrupts the running turn (`cli_tui_mixin.py:941-967`). (If a draft may be present in the buffer, press `Ctrl+C` twice >2s apart or clear draft first, or use `/stop`).
  4. **Double-`Esc` (`Esc Esc`) on an empty buffer while busy (Ink TUI)**: Interrupts the running turn (`ui-tui/src/app/useInputHandlers.ts:104-123`). Note: in the classic `prompt_toolkit` CLI, `_tui_handle_double_escape` (`cli_tui_mixin.py:1045-1060`) only discards a draft; in the Ink TUI, `Esc Esc` when **idle** with an empty buffer opens the `/rewind` picker (`useInputHandlers.ts:125-135,171-183`).

### 3.2 Editable `/queue` (`hermes_cli/cli_loops_mixin.py:520-546`)
- **What changed upstream:** `/queue` now parses management subcommands when the first word after `/queue` is `add`, `list`, `clear`, `edit`, `rm`, or `move` matching management syntax (`cli_loops_mixin.py:520-546`):
  - `/queue list` or `/queue clear` (with no trailing arguments) lists or clears the queue instead of enqueueing!
  - `/queue edit <N> ...`, `/queue rm <N>`, `/queue move <A> <B>` (where `<N>`, `<A>`, `<B>` are integers) edit, remove, or reorder queue items instead of enqueueing!
  - `/queue add <prompt>` forces enqueueing any prompt text unconditionally (`cli_loops_mixin.py:532-537`).
- **Impact on `repl_inject` / `orch-waker` / `orch_message`:**
  - `orch-waker` prefixes nudges with `[orch-waker] board ...` (`hscc_daemon/orch_waker.py:437`) and `orch_message` prefixes nudges with `[from <sender-orch>] ...` (`hscc-cluster/orch_message.py:94,257`), so neither ever starts with a bare management verb.
  - However, `hscc-api/repl_inject.py:73` sets `VERB_PREFIX = {"plain": "", "queue": "/queue ", "steer": "/steer "}`. If a human or `hscc orch inject` sends a raw message like `"clear"` or `"list"` or `"rm 1 ..."` while the pane is busy, `/queue clear` would clear the orchestrator's queue instead of enqueueing the message!
  - **Fix (optional hardening):** Change `"queue": "/queue "` to `"queue": "/queue add "` in `hscc-api/repl_inject.py:73` (`cli_loops_mixin.py:532` guarantees `/queue add <rest>` always enqueues).

### 3.3 `session_reset` Idle/Daily Modes Retired
- **What changed upstream:** `session_reset` `idle` and `daily` timer modes are retired (`v0.22.0.md:52,166`; `hermes_cli/session_reset_retirement.py:1-45`, `hermes_cli/doctor_config.py:584-590`). ## 4. Overlaps Worth Adopting or Retiring (Recommendations Only)

1. **Worker retry-in-place (`v0.22.0` #112318/#112500, `v0.23.0` `agent.auto_recovery_cycles: 5` at `config_defaults.py:121-127` & `kanban_owner_recovery.py:1-250`) vs HSCC watchdog/proxy-stall heal and `pom11/hermes-agent#3` jitter:** **Keep HSCC proxy-stall watchdog; retire `pom11/hermes-agent#3` jitter** — upstream now retries transient 503/529/timeouts in-turn with jittered `15/30/60/60/60s` backoff (`config_defaults.py:122-127`) and requeues rate-limited kanban workers without burning retry budget (`hermes_cli/kanban_db_dispatch.py:1224`), but cannot restart a wedged LiteLLM proxy or vLLM container like HSCC's daemon does.
2. **Local stream stall timers (`agent.local_stream_stale_timeout: 900`, `agent.turn_liveness.timeout_s: 600` at `config_defaults.py:259,282`; sleep-aware in `v0.22.2` #138560) vs `pom11/sparkrun#1`:** **Keep both (complementary layers)** — Hermes's `turn_liveness` (`600s`) and `local_stream_stale_timeout` (`900s`) abort a wedged client turn inside the agent loop, while `sparkrun` / LiteLLM proxy timeouts govern backend upstream socket reads across the cluster.
3. **Per-chat MCP tool spend limits (`v0.23.0.md:28,168`, #142470/#143787) vs HSCC card budget hook (`hscc-cluster/budget_watch.py:56-66`):** **Keep HSCC `budget_watch.py`** — upstream's spend limit only tracks USD prices declared on paid MCP tools and prompts for human approval, whereas `budget_watch.py` tracks LLM context size (`120K` prompt tokens) and API call count since last git commit (`40` calls) to trigger autonomous `DONE`/`LEFT` card handoffs.
4. **Subagent Steer/Stop (`v0.22.0.md:35` `F6`/`Ctrl+T`/`/stop`, `v0.23.0.md:94`) vs HSCC kill switch (`hscc_daemon/kill_switch.py:109-225`):** **Keep HSCC kill switch** — upstream Steer/Stop operates on in-session `delegate_task` child subagents from an interactive composer, whereas `hscc_daemon/kill_switch.py` enumerates and terminates standalone `hermes kanban` worker processes across all boards via REST/CLI (`GET/POST /v1/kanban/running`).
5. **Waiting-on-you notification (`display.bell_on_prompt: False` at `config_defaults.py:837`, OSC 9 + desktop notification on clarify/approval/sudo) vs HSCC notifier (`hscc_daemon/desktop.py`, `orch_waker.py`):** **Keep HSCC notifier and leave `bell_on_prompt: false`** — upstream notifies a human when an interactive chat blocks on an approval/clarify card, whereas HSCC's `orch_waker` and daemon notifications alert orchestrator panes and the operator on kanban card transitions and cluster health events.
6. **`delegation.prefix_stagger_seconds` (`config_defaults.py:1360`, `v0.23.0.md:92` #86553) vs proxy session affinity:** **Adopt `delegation.prefix_stagger_seconds: 2` only for single-backend endpoints; keep `0` behind the multi-node LiteLLM worker proxy** — waiting for the first child's first chunk warms the KV prefix cache on a single vLLM replica, but behind a multi-node load-balanced proxy without prefix-sticky routing, sibling subagents hit different GPUs and the stagger only adds latency.
