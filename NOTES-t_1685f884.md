# t_1685f884 — Monitor Live Activity: real cluster metrics on every surface

Base: `origin/main` @ `89bd2ae6` (parent t_61ed3f5e's `ClusterMonitorViewModel` is merged,
so this card builds on it directly — no cherry-pick needed).

## Goal (from the card)

Enrich the Monitor Live Activity so Lock Screen, Dynamic Island compact
(leading + trailing), expanded (leading/center/trailing/bottom) and minimal all
carry **real cluster metrics** instead of a summary, using the shared view-model.
The app-side driver stays the refresh owner; the extension never fetches.

## Design decisions (mine, as the implementing worker)

### D1 — Formatting is not re-implemented in the extension

`Sources/Shared/ClusterMonitorViewModel.swift` is the single owner of every
`hscc cluster monitor` cell (its parity contract is `model_decode_check` vs
goldens generated from `hscc_daemon/cluster_live.py`). The extension must not
re-derive units or rounding, so the **driver** projects the CLI cells
app-side and pushes already-formatted strings, together with the
`ClusterMetricLevel` verdicts the view-model already computes
(`cpuTempLevel`, `gpuTempLevel`, `gpuPowerLevel` — the view-model's own
thresholds, warn 80 / critical 90 °C; power vs its own `gpu_power_limit_w`).
The extension maps level → `WidgetStyle` colour and draws strings. One
formatting owner, one threshold owner.

### D2 — New payload lives in a new Foundation-only file

`MonitorActivity.swift` imports ActivityKit, so nothing in it can be compiled
by a macOS harness whole (gate-map: only `GATE-SLICE` blocks survive there).
The new metric types + every per-surface decision therefore go in a **new
Foundation-only file**, `Sources/Shared/MonitorActivityMetrics.swift`, which
`model_decode_check.sh` compiles and *runs* — the same shape
`ClusterNodeTally.swift` / `CardsRunningProjection.swift` established. The
payload structs it declares are what `ContentState` stores.

### D3 — New `ContentState` fields are all optional and defaulted

`MonitorActivityAttributes.ContentState` is serialized by ActivityKit and can
outlive an app update, so every new field is `T? = nil` and every surface
falls back to what it renders today when the field is absent. Defaults go on
`init` parameters, never on stored properties (the `= nil` decode trap).

Fields:

| field | meaning |
| --- | --- |
| `hostRows: [MonitorHostMetric]?` | the CLI host table, one entry per host |
| `servingTotals: [MonitorServingTotalMetric]?` | the CLI `total (n)` rows, per model |
| `servingRunning / servingWaiting: Int?` | the serving table's aggregate Run/Wait (`ServingSummary`, so "not told" stays nil, never 0) |
| `servingBackends: Int?` | live backend rows (the CLI's `total (n)`) |
| `primary: MonitorPrimaryMetric?` | the one honest metric for compact + minimal |
| `hostRowsDropped: Int?` | how many hosts the push cap left out (honest truncation) |

`MonitorHostMetric` carries the display label, the nine CLI cells verbatim
(`jobs … gpuPower`), the host's own serving `running`/`waiting`, and the four
levels it needs for colour.

### D4 — The compact/minimal primary metric, and why it is not a fleet average

`hscc cluster monitor` has **no** fleet-wide GPU% aggregate on the wire, so
inventing a mean would be a number no route sends (§6 rule 1). The card's
"total GPU%" is therefore realised as the *busiest single host's* GPU%,
labelled with that host. Selection order (one executable func, gated):

1. hottest **GPU** temp across the hosts that reported one;
2. else hottest **CPU** temp;
3. else busiest **GPU util**, labelled with its host;
4. else the serving `running` total (when the serving section was told at all);
5. else the node tally `up/total`;
6. else nothing — the surface renders `—`, never `0`.

Compact leading = that primary (short form), compact trailing = a secondary
(serving `run/wait` when told, else the node tally), minimal = the primary
alone, falling back to the state dot when nothing is known.

### D5 — Size budget

ActivityKit caps the serialized attributes + content state (~4 KB), so the
push caps rows (`maxHostRows = 6`, `maxServingTotalRows = 4`) and records
`hostRowsDropped`; the views clip *again* locally (a pushed ContentState is
untrusted input to a fixed-height region — the `ClusterHealthDetail`
precedent): Lock Screen 4 rows, expanded 3, compact/minimal none.

### D6 — Per-surface content

* **Lock Screen**: state header + tally + age, then one row per host —
  label, `GPU%`, `GPU temp`, `CPU temp`, `GPU power W` (CLI cells) and that
  host's serving `run/wait` — then a serving-totals line per model
  (`total (n) · model · run/wait`), then the daemon-host line.
* **DI compact**: leading = primary metric (temp or GPU%), trailing =
  secondary (serving run/wait, else tally).
* **DI expanded**: leading = state dot; center = headline + primary line;
  trailing = tally; bottom = the host table (≤3 rows, CLI cells) + the
  serving totals line.
* **DI minimal**: the primary metric alone; the state dot only when no metric
  is known.

`showSections` keeps its meaning: `nodes` gates the host rows, `host` the
daemon-host row, `state` the headline — a section that is off pushes nothing,
and the surfaces degrade rather than lie.
