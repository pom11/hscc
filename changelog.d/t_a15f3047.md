- **Orchestrators can now nudge each other, and only each other.** New tool
  `orch_message(to, message, ref_card=None)` in the `hscc-cluster` plugin: an
  orchestrator profile hands a short note to another orchestrator profile's
  live REPL through `repl_inject`, with the sender auto-signed
  `[from <sender-orch>] ` (plus `re: t_xxxx` when `ref_card` names a task).
  Enforcement is in code, not prose: the sender must be the *running*
  profile and both ends must be `*-orch` profiles (workers and `default` are
  refused); delivery is QUEUE-ONLY — `mode="auto"` (`/queue` while the target
  is busy, a plain send when idle) and `steer` is never chosen by this tool,
  so a nudge never cuts off a running turn; the pane must resolve to exactly
  one target (missing or ambiguous pane = refusal, inherited from
  `repl_inject`'s exactly-one-pane rule). Per-`(sender, to)` rate limit of
  **6 messages per hour by default** (`orch_message_max_per_hour` in
  `~/.hscc/cluster.json`, `HSCC_ORCH_MSG_MAX_PER_HOUR` env override) plus a
  reply loop guard: a message that arrived already signed `[from ` may not be
  answered with another `orch_message` inside the same turn. Every call — sent
  or refused — appends one JSONL line to `~/.hscc/state/orch_messages.jsonl`
  with `ts`, `from`, `to`, `ref_card`, `chars`, `delivered`, `verb`, `reason`,
  pane and the first 200 characters of the body; the full body is never
  stored.
