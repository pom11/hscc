- **`ios-app/scripts/widget_settings_check.sh` executed its own Swift comments
  as shell.** The gate writes its harness with an UNQUOTED heredoc
  (`cat > "$WORK/main.swift" <<SWIFT`) on purpose — `$suite_container` and
  `$model` are expanded into it, and that verbatim extraction out of
  `Sources/Shared/SharedStore.swift` is the whole reason the gate cannot drift.
  An unquoted heredoc also runs every unescaped backtick it contains as a
  command substitution, and three Swift comment lines had backticked prose
  (`defaults.surfaces.count == 4`, `defaults()`, `surfaces`), so bash executed
  them on every single run: `command not found` ×2 plus a `syntax error:
  unexpected end of file` on stderr, while the gate still exited 0 with all its
  assertions green. It looked benign because the substitutions expanded to
  nothing and landed inside comments — but capture the generated harness and
  the damage is visible: **six backticks had been deleted from the code this
  gate compiles and asserts on**, every unescaped one, the balanced pairs
  silently and the unbalanced ones loudly. Whatever a backticked word resolves
  to is what gets compiled, so the next such comment — a `git …`, a shell
  snippet, a word that happens to name a binary — would have quietly changed
  what the gate proves while still printing ALL PASS. The three comments are
  now written with escaped backticks, which is what keeps the prose intact
  inside an interpolated heredoc; quoting the delimiter (`<<'SWIFT'`) would have
  been the wrong fix, since it kills the intentional extraction.

- **The harness is now byte-pinned, so this class cannot come back silently.**
  Two guards were added, because neither covers the other's case. A static scan
  of the committed `<<SWIFT` region refuses the file **before the heredoc is
  ever expanded**, naming the offending line numbers (proven by injecting
  `` // someone writes `git status` here `` at region line 300: refused, RC 1,
  zero stdout, no banner). And at the foot of the gate, before the harness
  binary is run, the generated `$WORK/main.swift` must be **byte-identical to
  the committed `ios-app/scripts/widget_settings_check.harness.golden`** and
  carry **zero unescaped backticks** (Swift has no backtick syntax at all, so a
  live one in the harness is by definition a splice). The byte comparison is the
  half a scan of this file cannot be: it also sees splices arriving through
  `$model`, which is extracted from `Sources/` at run time. Both refusals print
  the refresh path (`WSC_UPDATE_GOLDEN=1 …` plus `git add` of the golden) so an
  INTENDED change to the extracted model block is a deliberate, reviewable act
  rather than a gate nobody can re-run.

- **The macOS awk trap that made the first draft of this guard hang forever:**
  BSD awk treats a `$` in the MIDDLE of a regex as a literal dollar sign, so
  `match(head, /\\$/)` never fails on ordinary text and an escape-parity loop
  written that way spins instead of terminating. The counter here spells the
  trailing-backslash test with `substr()`, which behaves identically in every
  awk, and the note is left in the script so the next person does not lose an
  afternoon to it.
