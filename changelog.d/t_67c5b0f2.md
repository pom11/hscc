- **The iOS Fleet screen now says when the server's own health verdict is old.**
  PR #486 made `GET /v1/health` answer from a cached verify snapshot and gave
  the payload four new keys — `age_seconds`, `generated_at`, `stale` and
  `source` — while `ConnectionMonitor` keeps polling that route every 15 s. The
  app decoded none of them, so a five-minute-old fleet verdict rendered exactly
  like one that had just run: the server had stopped implying a fresh check, the
  screen had not. `HealthResponse` (`ios-app/Sources/HSCC/Models.swift`) decodes
  all four as **optional** (`Int?` / `Bool?` / `String?`), so a server older
  than PR #486 — which sends none of them — still decodes, and `FleetView`'s
  Health section adds a `Server says this verdict is N old · from cache` row
  when the server flags `stale`. The age reuses the app's one and only relative
  age formatter, `Offline.agePhrase`, the same one the offline `StaleBanner`
  already renders, and the server's `speak` stays on screen verbatim — it
  already carries the `Health from 4m ago.` sentence. When `stale` is true but
  the server sent no age, the row says the verdict is stale and prints **no
  number** rather than defaulting to `0s`, which would be the very implication
  this change exists to remove. Nothing about what the app *asks* changed: the
  endpoint stays `/v1/health` at the same cadence and no `/v1/verify` call was
  added — that route runs the whole fleet smoke test with real GPU chat
  round-trips.
