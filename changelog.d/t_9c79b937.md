- **`changelog.d/README.md` documented a filename gate that did not exist.**
  A fragment named anything but a kanban task id — `misc.md`, `chore.md` —
  passed `changelog_fragments.py check` with rc=0, got counted, and would be
  materialised into the next release. `TASK_ID_RE` existed but was consulted
  only by `add` and `rescue`, i.e. by the commands validating the id they were
  *given*, never by the path that reads the files that are *present*, so a
  hand-authored shared fragment bypassed it completely. `load_entries` — the
  one funnel every command (`list`/`render`/`sync`/`check`/`release`) goes
  through — now rejects a live fragment whose stem is not `t_<hex>` as a
  malformed fragment (stderr `malformed fragment: <file>: …`, rc=2), which is
  the documented 0/1/2 convention and the same shape as the missing-separator
  gate from t_f57b9d82. Filename ownership is what keeps worker diffs disjoint,
  so a shared fragment reintroduces exactly the merge conflict this scheme
  exists to remove; now it fails at check time, not at merge time. The gate
  applies to the live directory only: `changelog.d/archive/**` keeps its
  pre-scheme names (`t_tmux_chat_20261013.md` et al.) and must stay parseable
  for audit, so the rule is a property of the directory being loaded, not of
  the parser. Selection of fragment files also became case-insensitive on the
  `.md` suffix, so `misc.MD` cannot hide from the gate (or from `check`) on a
  case-insensitive filesystem.
