- **A new daemon stream catches alive-but-starved model streams (incident 2026-11-05).**
  `stream_silence.check_stream_silence` runs every 60 s and compares each
  running kanban card's dispatcher heartbeat (`kanban_live.collect`, read-only)
  and each configured orchestrator's live agent.log against the newest
  `latency=` completion line in that profile's `agent.log`. A session whose
  last completion is older than the 600 s threshold **while its heartbeat is
  fresh** gets a WARN log line, a persisted state entry, and one desktop notify
  per 30-minute per-session cooldown; stale heartbeats (dead panes) are
  suppressed because `orch_waker` owns them, and a missing completion signal
  is reported as `○` (unknown), never guessed. Orchestrator heartbeats use the
  log mtime, so a genuinely idle REPL stays quiet while a hung one that keeps
  emitting `Stream stale` warnings does not. The stream always publishes
  `ok: true`; `hscc verify` gains a `stream_silence` row that lists the ages
  and is never red by itself. Tests are hermetic (fabricated tmp logs and fake
  roster/notify/state seams).
