- **A packed leg the harness could not run now says so, instead of wearing the
  shape of a red test.** `scripts/run_tests.sh`'s pack reaper already knew two
  facts that separate the classes — the leg's own `.rc` record is missing, and
  the leg's own log holds nothing — but reported both as the ordinary
  `✗ <leg> (pytest exit N, Xs)`. That is why the `.github/scripts` log-path bug
  (t_692814f5) hid for a release: a leg whose `> "$logf"` could not be opened,
  which never spawned pytest, printed `✗ .github/scripts (pytest exit 1, 0s)`.
  The pack now emits `✗ <leg> (no leg output — harness failure, pytest exit N,
  Xs)` and marks the live `parallel: done` line `record=missing`. The row keeps
  its `✗` anchor, its verbatim leg name and the literal `pytest exit N` token,
  so `merge_queue._LEG_FAILURE_RES` and the serial/duration/parity pins are
  untouched; the class is pack-only because the `.rc` record is a pack-only
  artefact, and the serial row is unchanged byte-for-byte. The empty log is
  load-bearing, not decoration: a leg that printed `FAILED path::test` before
  its wrapper died has real evidence about a test and keeps the ordinary row.
- **`.github/scripts/leg_verdict.sh` stops routing that class to the advisory
  branch.** Its existing rule hard-reds `pytest exit` with any code but 1, so
  the redirect instance — where `wait` leaves **1** — was reported as an
  ordinary test failure: `::warning::` and a GREEN check while
  `HSCC_TESTS_ENFORCE` is unset. A leg that never ran is now a hard red
  regardless of that variable. The pattern is anchored on a summary row
  (`✗ <leg> (no leg output`), so a real test failure whose own output merely
  mentions the words stays advisory.
