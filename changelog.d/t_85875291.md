- **`GET /v1/autodown/status` wrote the daemon's log — verdict: a read route may
  not** (t_85875291, PR #723's machine twin). The route shares
  `hscc autodown status`'s payload builder, so on a host with an unreachable
  Hermes library one authenticated `GET` appended the kanban interlock WARN to
  `$HSCC_HOME/daemon.log` — the **daemon's** rotating log, from the API process,
  on a surface its own docstring calls read-only. Verdict + evidence in
  `docs/audits/verdict-api-autodown-status-read_t_85875291.md`: the parent
  audit's ACCEPTABLE list is about actors (the daemon's loops, `hscc check`) and
  never mentions the API; the repo's convention is that a process writes **its
  own** log (`api_cli.py` passes `log_file=API_LOG_FILE` on every API
  diagnostic, and `daemon.log` is a rename-rotated `RotatingFileHandler`, so a
  foreign writer is a lost-write hazard, not a cosmetic one); and
  `metrics_history.resident_recorder` already settled that a read route in this
  separate process must not cause daemon-side effects. Fix is PR #723's smallest
  shape — `autodown.silent_read()` around the ONE borrowed call, kanban leaf
  only, so the PR/CI WARN stays audible (t_18318fd9) and the once-per-process
  WARN budget is deferred, not spent. Guarded in the surface's own suite
  (`hscc-api/tests/test_routes_autodown.py::TestTheRouteWritesNoDaemonLog`: a
  real server + a real GET in a sealed `HOME`, the payload required to name the
  sandbox path, `activity.json` required to appear so the handler really ran, and
  an un-muted control that must still see the WARN). Red-before: 1 failed quoting
  the written line; green-after: 2 passed.
