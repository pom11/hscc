- **Three `doctor` budget-hook tests failed on every deployed host since the
  2.15.0 root deploy** (`hscc-bootstrap/tests/test_doctor_budget_hook.py`:
  `test_missing_register_hook_lines_are_red_naming_the_fix`,
  `test_import_failure_is_non_fatal_degraded`,
  `test_broken_module_is_non_fatal_degraded`; green on clean CI, so the gate
  never saw them). The fixtures deploy an isolated tree under `tmp_path` and
  hand it to the row as `hermes_home`, but they never stubbed the resolver's
  *env* inputs: `doctor._budget_plugin_dirs()` appends `~/.hermes/plugins` as
  its last candidate (`doctor.py:1580`, read via `expanduser`), and
  `budget_watch.doctor_check()` scans EVERY root it is handed and passes if ANY
  is wired. On a machine whose `~/.hermes/plugins` carries a wired
  `hscc-cluster` — every fleet host since 2.15.0 — the LIVE tree joined the
  candidates and the row answered ok=True ("... wired in
  `~/.hermes/plugins (this module: repo copy)`") where the test asserted the
  degraded/unverifiable verdict. The tests were reading the operator's install
  instead of the fixture, and the `wired→green` case was passing off the live
  tree too without noticing. `_seal_plugin_env()` now points every input the
  resolver reads at the fixture (`HOME` → `tmp_path`, so the `~/.hermes/plugins`
  tail lands inside the tmp dir; `PLUGINS` unset, since an inherited worker
  value outranks even the fixture) and asserts both that the fixture root IS a
  resolved candidate and that the operator's real root is NOT — the second
  assertion is the tripwire: a future resolver change that re-admits a live
  root fails with "plugin-root resolution reached the live operator tree"
  instead of silently flipping a verdict. Tests only; no production change.
