### Fixed

- **`Unknown skill(s)` on spawns — collision guard + reviewer readiness (t_bc611809).**
  Profile-local skill-name collisions (a stale flat `skills/<name>` copy from
  an old bootstrap next to hermes' category copy `skills/<category>/<name>`)
  and genuine absence (a profile without `sdlc-review` at all) both made the
  dispatcher's review-lane force-injection die with
  `ValueError: Unknown skill(s): sdlc-review` → worker exit 1 → counted crash.
  New `hscc-bootstrap/skill_guard.py` mirrors hermes' resolver rules
  (collision refusal, same-root identical-copies ranking, legacy flat `.md`
  candidates, `external_dirs` scan set); `install_review_skill.py` now
  installs **only** where the name resolves nowhere (collision skips are
  reported with every colliding path, reviewer-capable profiles only for
  missing installs, no-ops otherwise, `--dry-run` writes nothing) and
  `hscc-skills hscc.py install-skills` routes every bundled write through the
  same guard. `doctor.py` gains two non-fatal findings — duplicated skill
  names per home, and `sdlc-review` resolving exactly once for every
  reviewer-capable profile — plus a deterministic `doctor.py --skills --home`
  fast mode for acceptance re-runs. `bootstrap.sh` runs the guarded fan-out as
  a warn-not-die stage. hscc never deletes or overwrites a resolving copy:
  colliding pairs are reported for the operator to adjudicate.
