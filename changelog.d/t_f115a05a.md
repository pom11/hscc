- **A dead sidecar read as ALIVE, so a green teardown red-gated a queue run (the
  `hscc-api` leg of PR #836).** `_alive` probes twice — `kill(pid, 0)` first, then
  `ps -ww -o state=,command= -p` — and the second answer was thrown away whenever
  it came back empty: empty output became `UNKNOWN`, and `UNKNOWN` is reported as
  *alive*. Measured on macOS, a reaped pid makes that `ps` exit **1** and print
  **nothing** — it is answering "there is no such process", the same statement the
  `/proc` branch already makes from a missing `stat`. So when the reaper lands
  between the two probes, the assertion taken right after `_wait_until_gone` has
  already seen the pid go — `assert not _alive(info["pid"], serve_marker)` —
  answers "alive" and reddens on a serve that is verifiably dead. Now a probe that
  RAN and reported no such process is `DEAD`. A `ps` that could not run stays
  `UNKNOWN`, and an empty answer with a ZERO exit stays `UNKNOWN` too: "gone" is
  the answer that can hide an orphan. No bound widened, nothing skipped, retried
  or re-timed.
