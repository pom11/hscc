### Added

- dep-bump guard (t_39d7c915): the runtime dep-bump flow now knows sparkrun runs
  from OUR FORK BRANCH. Canonical rule in `hscc_daemon/dep_bump_guard.py`
  (branch `feat/proxy-least-in-flight`, remote `pom11/sparkrun`): a sparkrun bump
  REBASES the fork branch onto the new upstream tag and keeps it checked out —
  never `git checkout main`, never reinstall from upstream (that silently drops
  the proxy `router_settings` passthrough and the least-in-flight balancer). The
  rule is injected into the CI-generated bump PR body
  (`.github/scripts/check_runtime_deps.py`) and the dep-watcher verification
  card (`scripts/dep_pr_watcher.py`) for sparkrun bumps only, and into the
  runtime-bump skill (`references/runtime-bump-verification.md`).
- `hscc verify` check `proxy_router_settings` + `hscc_daemon/proxy_router.py`:
  pure-read comparison of `~/.config/sparkrun/proxy.yaml` (router_settings +
  gateways.litellm.balancing) against the live
  `~/.cache/sparkrun/proxy/litellm_config.yaml`. WARN-only (never fails, never
  writes, never restarts); flags divergence, a requested balancer absent from
  litellm_settings.callbacks, non-mapping router_settings, unimplemented
  balancing values, and the `routing_strategy: least-busy` trap (no-op on the
  pinned LiteLLM — the working knob is `gateways.litellm.balancing:
  least-in-flight`).
- The daemon `proxy` stream now records the drift verdict (`router_drift` +
  `router_drift_warn`) on both the healthy and unhealthy state writes and logs
  a WARN line while drift is live — a proxy can serve every alias yet route
  blind after a bump dropped the fork branch.
