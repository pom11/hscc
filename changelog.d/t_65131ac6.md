- **`test_signal_to_the_harness_takes_every_burner_with_it[2-130]` was not a
  timing flake: it was the *launch shape of the suite*.** `load_burners.sh` traps
  INT, TERM and HUP, and a POSIX shell is not allowed to `trap` a signal it was
  born ignoring — bash 3.2 obeys that. An inherited `SIG_IGN` is sticky: `execve`
  preserves it, CPython does not install its own SIGINT handler over one, and
  every child inherits it again. So when the suite is started as an
  **asynchronous command of a non-interactive shell** — `( pytest … ) &`, which is
  how `scripts/run_tests.sh` starts every leg in parallel mode and how all three
  audits reproduced this stall — the harness is born deaf to SIGINT, the kernel
  *discards* the test's SIGINT (t_44a09412 read a stalled harness from outside:
  `ignored INT=1 / caught INT=0`, while `caught TERM=1 HUP=1` —
  `docs/audits/load-burners-sigint-trace-stage_t_5f9fab03.md`), the trap never
  runs and the harness has no internal end: it dies only at its own 60 s
  watchdog. The same file launched in the **foreground** is born `SIG_DFL` and
  passes — which is the "sibling-suite dependent" and "tight race" readings
  reaching for, and neither is needed.
  **Ruling:** the launcher fixes it, not the assertion. `_running()` now passes
  `preexec_fn=_born_able_to_trap`, which resets INT/TERM/HUP to `SIG_DFL` in the
  child between fork and exec, so the harness is born able to trap the signals the
  harness's own contract says it handles, whatever shape started the suite. No
  skip, xfail, retry or widened timeout, and no change to `load_burners.sh`, to
  `run_tests.sh`, or to the arm's assertions.
  `test_the_reset_is_what_the_int_arm_rests_on()` pins the reset: it puts the
  suite process itself into the born-ignoring state, launches the harness from
  there, and still requires `exit 130` — so if the reset is ever dropped the
  suite goes red in *every* launch shape instead of the flake silently returning.

- Shape, measured rather than inferred (`probe_chain.py`): a suite-shaped python
  process launched `foreground sh -c …` reads
  `<built-in function default_int_handler>`; the same process launched as
  `sh -c '… &'` reads `<Handlers.SIG_IGN: 1>`. A `/bin/sh` born default traps a
  self-sent SIGINT (`CAUGHT`); a `/bin/sh` born ignoring does not (`NOBODY`) —
  the `trap` never installs.
- Red before, deterministically, at load 3.7–4.3 on 14 cpus
  (`sigint_shape_rig.sh`, base `a7041cf5`): **background 5/5 runs failed**
  (`1 failed, 2 passed, 4 deselected`, 11.7 s each — the 10 s `proc.wait` plus
  the rescue `terminate()`), **foreground 0/5** (3 passed, 1.6 s each). A
  reproduction that does not depend on CPU load or on a ms-wide race.
- Green after, same rig, same load: **background 0/5 failed** (`3 passed`,
  1.7 s each — the run time falling from 11.7 s to 1.7 s is the stalled harness
  gone), and `[2-130]` alone **20/20 runs passed** in the background shape with
  ten CPU burners alive, load 5.5–8.8 recorded per run (skill
  `hscc-ci-flake-triage` §3).
- Teeth by mutation, not by reading: delete the `preexec_fn` argument and the
  file goes `1 failed, 7 passed` — the failing case is
  `test_the_reset_is_what_the_int_arm_rests_on`, in the *foreground* shape, where
  the three ordinary arms still pass. That is the point of the pin: it catches the
  dropped reset in the launch shape that hides it.
- 0/20 and 0/5 against a 5/5-reproducible base is not by itself proof of
  elimination at a low rate — the real proof is this arm running inside every
  queued gate. What *is* proved here is that the failure has a shape, the shape
  is named, and the shape is severed.
