* `scripts/load_burners.sh` can now take the SIGINT that `cmd &` handed it. POSIX (sh spec, *Asynchronous Command*) makes a non-interactive shell give an `&` command SIGINT as `SIG_IGN`, the ignore survives `fork`+`execve`, and a shell may not `trap` a signal it inherited ignored — so bash 3.2 silently refused the harness's own `trap … INT`, the kernel discarded every SIGINT addressed to it, `cleanup()` never ran and the burners orphaned: the t_71ed3b1c incident recreated by nothing but how the process was started. Measured on one test file with no sibling suite and no load: `1 failed, 6 passed in 14.09s` as `cmd &` vs `7 passed in 4.14s` in the foreground, and `ignored INT=1 / caught INT=0` on the harness with SIGINT not delivered — so the `t_f8e6fe38` alone-vs-paired split (0/60 vs 4/4+2/2) was the launcher, not the second suite or CPU pressure. It is not confined to a diagnostic: `scripts/run_tests.sh`'s pack mode launches every leg as `( … ) &`.
* The harness restores its own disposition, because the harness owns the no-orphan guarantee: when `trap -p INT` reports no trap (exact on bash 3.2, and costs no process), it asks python3 — already a dependency of `new_group` — whether SIGINT is inherited ignored and, if so, re-execs the same script once through an interpreter that puts it back to `SIG_DFL`. Pid, session, argv and the output contract are preserved (argv is rebuilt from `$BURNERS`/`$LIMIT`/`$@`, because the parse-time `shift`s have already consumed the first two). TERM and HUP stay as inherited — `nohup` ignores HUP, and with those ignored the harness survives rather than orphaning — and `HSCC_LOAD_BURNERS_KEEP_SIGINT=1` keeps the caller's ignore. No test file touched, no timeout raised, no `loadstress` marker, wait/trap structure unchanged.
* `HSCC_LOAD_BURNERS_TRACE` gains a `sigint-reset` marker, so the fix path is observable in the trace the loadstress leg already uses. `docs/audits/load-burners-signal-owner_t_8bb39d12.md` records the 2×2 (disposition is causal; the async shape is neither necessary nor sufficient), the `trap -p` discriminator, and corrects both parent audits' "narrow startup race" wording: under such a launcher the SIGINT is lost every single time.
