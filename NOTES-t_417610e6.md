# t_417610e6 — orch profile auxiliary.* base_urls written node-direct

Status: IN PROGRESS (findings as of first commit)

## 1. Culprit (traced with evidence)

**`hscc-bootstrap/enable_plugins.py` — the module-level `COMPACT_URL` default.**

```
enable_plugins.py:97   ORCH_MODEL_HOST = os.environ.get("HSCC_ORCH_MODEL_HOST", "10.0.0.244")
enable_plugins.py:124  _DEFAULT_COMPACT_URL = f"http://{ORCH_MODEL_HOST}:8000/v1"
enable_plugins.py:125  _COMPACT_URL_RAW = os.environ.get("HSCC_COMPACT_URL", _DEFAULT_COMPACT_URL)
enable_plugins.py:127  COMPACT_URL = _COMPACT_URL_RAW
```

The constant `10.0.0.244` is hardcoded at :97, so it does **not** come from any
template or from serving.json — which is exactly why `check_profile_endpoints`
could never have flagged it (see §3).

Two writers inside `enable()` consume `COMPACT_URL` and are the only code in
the repo that stamps a node-direct URL into `auxiliary.*`:

```
enable_plugins.py:426-433   _ensure_compaction()      -> auxiliary.compression.*
enable_plugins.py:463,482   _ensure_text_auxiliaries() -> the 8 text auxiliaries
```

### Fingerprint match against the operator backup (read-only)

`~/.hscc/backups/hscc-orch-config.yaml.bak-20261104-1015` carries 9 entries with
`base_url: http://10.0.0.244:8000/v1` + `model: orchestrator-model`
+ `provider: custom` + `api_key: sk-sparkrun`. Mapping each field:

| field | value in backup | writer that produces it |
|---|---|---|
| `model: orchestrator-model` | the **ORCH_MODEL alias** | only enable_plugins `COMPACT_MODEL` (:126-128 — ORCH_MODEL when URL==_DEFAULT_COMPACT_URL) |
| key order `provider, base_url, model, api_key` on the 8 text aux | matches | `_ensure_text_auxiliaries` fill order `base_url, model, api_key` after `provider` was set (:479-486) |
| key order `base_url, model, provider, api_key, timeout` on compression | matches | `_ensure_compaction` fill order `base_url, model, provider, api_key` then `timeout` (:429-437) |
| `timeout: 90` on compression, absent on the 8 | matches | `COMPACT_TIMEOUT` (:436) — `_ensure_text_auxiliaries` never writes timeout |
| `provider: custom` (a value, not empty) | present | the 8 could only be filled *because* prov was empty/auto |
| `goal_judge` + `fallback_providers` + `delegation` on **localhost:4000** | correct | `WORKER_PROXY_URL`-based writers (:504, :347) in the same `enable()` pass |

9 = 1 (`_ensure_compaction`) + 8 (`_ensure_text_auxiliaries`). That is the exact
pair. `_ensure_goal_judge` ran in the same call and correctly used the proxy,
which is why `goal_judge` survived clean while its 9 siblings did not.

### Why `main` / `goal_judge` / `fallback` stayed on the proxy

They are routed from `WORKER_PROXY_URL` (:75, default `http://localhost:4000/v1`)
— `_ensure_delegation`, `_ensure_goal_judge`, `_ensure_fallback`. Only the
*compaction-family* consumers read `COMPACT_URL`, and `COMPACT_URL`'s only
default is the node.

## 2. Ruled out (with evidence)

- **`hscc-cluster/cluster_template.py:2316 / 2776`** — :2316 is
  `_build_models_json` (writes `~/.hscc/models.json`, not any profile config).
  :2776 is the **non-uniform legacy** branch of `_update_hermes_config`, and it
  writes only `providers["custom"]` — never `auxiliary.*`. Grep for `auxiliary`
  in that file returns only :3560/:3562 (`_routing_config_keys`), which resolve
  through `_routing_target_endpoint` (:3475) — and that yields `localhost:<proxy>`
  for every `family-*` target with a proxy. So the apply path **cannot** have
  produced a node-direct auxiliary under a uniform_pool plan.
- **`hscc-roles/generator.py`** — orch profiles get `config["model"] =
  _strong_model_block()` and `config["compression"] = _compression_block(...)`
  (:742-756). They never receive `auxiliary` at all: only
  `_worker_compaction` (:447-460) writes an `auxiliary` block, and only for
  non-orch worker roles. The card's "worker path uses COMPACT_BASE_URL and is
  NOT suspected" is confirmed; and the *orch* path writes no auxiliary either.
- **Old template snapshot (`configs/hscc-config.yaml.template`)** — carries
  `nodes: [10.0.0.244, ...]` but no `auxiliary` key and no profile-config
  interpolation path; nothing reads that file into a profile config.
- **`hscc_daemon/verify.py check_provider_routing`** — would have caught this,
  but only fires when the applied template records `uniform_pool` (:1111-1116
  returns `skipped:` otherwise). Not a writer, and it evidently did not fire.

### Why the poison SURVIVED (second half of the bug)

Both writers are fill-empty: `_ensure_compaction` :431
`if want and not (aux.get(key) or "").strip()` and `_ensure_text_auxiliaries`
:475 `if prov not in ("", "auto"): continue` + :484. So once a wrong
`base_url`/`provider: custom` was on disk, **every later bootstrap and every
`doctor --fix` (doctor.py:2392-2393 calls `enable()`) refused to correct it** —
it read the wrong value as a deliberate operator choice. That is why the wrong
value persisted through many re-enters of the same code that could not have
written it a second time.

## 3. The pin gap

`hscc_daemon/verify.py:881 check_profile_endpoints` already walks **every**
nested `base_url` in every profile config (`_collect_profile_urls`, :860-878 —
which is how it sees `auxiliary.*` today) and compares by origin against
`{orchestrator endpoint from serving.json, proxy}` + loopback (:937-956).

The hole is `orchestrator_endpoint` itself (`hscc_daemon/serving.py:209`):
under a **uniform pool** serving.json legitimately lists `10.0.0.244` as an
orchestrator unit node, so the node origin is admitted into `allowed` and the
node-direct auxiliary URL passes. The orchestrator endpoint is a valid *serving*
origin but is not a valid hermes *route* under a pool — hermes must only reach
the proxy.
